# NNTP Test Server

## Purpose

Add a deterministic NNTP server fixture for end-to-end tests of remote
news sources.  The fixture should be easy to start from local test data,
work in CI without privileged ports or external daemons, and make server
behavior explicit in a checked-in config file.

This is a fake NNTP reader server, not a small INN.  It should implement
only the protocol surface needed by `trn`, `nntplist`, and `inews`
tests.

## Direction

Use a stdlib-only Python script under `tests/support`.  The script reads
a JSON config, binds `127.0.0.1` on port `0`, writes the chosen port to a
port file, then serves until its parent wrapper stops it.

JSON is the config format because it is available in every Python build
we are likely to find in CI.  The fixture data can be generated by CMake
from the existing article, active, newsrc, and access templates.

The CTest entry should not know the port at configure time.  A Python
wrapper should start the server, read the port file, write any runtime
access file that needs `127.0.0.1;<port>`, run the test command, and
then stop the server.

## Protocol Surface

The first implementation should cover the normal reader path:

- greeting: `200` or `201`
- session: `CAPABILITIES`, `MODE READER`, `DATE`, `HELP`, `QUIT`
- group lists: `LIST`, `LIST ACTIVE`, `LIST NEWSGROUPS`,
  `LIST OVERVIEW.FMT`, `LISTGROUP`, `NEWGROUPS`
- group selection: `GROUP`
- article tests: `STAT`, `NEXT`, `LAST`
- article reads: `HEAD`, `BODY`, `ARTICLE`
- overview and headers: `XOVER`, `OVER`, `XHDR`, `HDR`
- posting: `POST`

Unsupported commands should return a deterministic `500` response.  A
config switch can later change selected commands to fail with specific
codes for retry and error-path tests.

## Config Shape

The config should be compact and data-oriented.

```json
{
  "greeting": "200 trn-test NNTP server ready",
  "date": "20260713190000",
  "posting": "allowed",
  "groups": [
    {
      "name": "alt.binaries.fractals",
      "status": "y",
      "description": "Fractal images and discussion",
      "created": "20260101000000",
      "articles": [
        {
          "number": 623,
          "path": "test_data/spool/alt/binaries/fractals/623"
        }
      ]
    }
  ]
}
```

Article files are normal RFC-style article text.  The server should parse
headers once at startup, preserve article bytes for `ARTICLE`, split
header and body for `HEAD` and `BODY`, and derive overview fields from
the parsed headers.

## Runtime Rules

- Listen only on loopback.
- Use CRLF on the wire.
- Dot-stuff multiline replies and posted article input.
- Keep all fixture state in memory.
- Accept multiple sequential client connections.
- Serialize each connection on its own thread.
- Log client commands and server replies to an optional log file.
- Exit nonzero if the config is invalid.

## CMake And CTest Wiring

CTest should run the fixture through a wrapper, not by relying on a
long-lived background service.  The wrapper owns:

- server process lifetime
- port-file polling with timeout
- runtime access file generation
- environment setup, including `NNTPSERVER=127.0.0.1;<port>`
- child test exit-code propagation
- server log capture

The first consumer can be a narrow `nntplist` end-to-end test.  That
keeps the first slice small: connect to the fixture, run `LIST`, and
compare output with expected active-file content.  Later slices can add
`trn` session flows and posting through `inews`.

## Implementation Slices

### Slice 1: Server Skeleton

- Add `tests/support/nntp_test_server.py`.
- Parse and validate the JSON config.
- Bind loopback on an ephemeral port.
- Write the chosen port to a port file.
- Implement greeting, line read/write, `QUIT`, and `HELP`.
- Add a smoke test that connects with a raw socket.

### Slice 2: Static Group Data

- Load groups and article files from config.
- Implement `LIST`, `LIST ACTIVE`, `LIST NEWSGROUPS`, `GROUP`,
  `LISTGROUP`, and `DATE`.
- Generate a sample server config from existing CMake test data.
- Add a focused CTest that exercises `nntplist`.

### Slice 3: Article Retrieval

- Parse headers and bodies at startup.
- Implement `STAT`, `HEAD`, `BODY`, `ARTICLE`, `NEXT`, and `LAST`.
- Add tests for missing articles and dot-stuffed article lines.
- Add an end-to-end test that reads an article from the fixture.

### Slice 4: Overview And Header Commands

- Implement `LIST OVERVIEW.FMT`.
- Implement `XOVER`, `OVER`, `XHDR`, and `HDR`.
- Cover the normal `trn` overview path.
- Cover the configured `XHDR Broken` fallback path.

### Slice 5: Posting

- Implement `POST` with allowed and prohibited modes.
- Store accepted posts in memory and optionally write them to a capture
  file.
- Add an `inews` end-to-end posting test.
- Add failure-mode tests for `440` and `441`.

### Slice 6: Trn End-To-End Wiring

- Add `tests/support/run_nntp_fixture.py`.
- Generate a runtime access file with `127.0.0.1;<port>`.
- Add a scripted `trn` run that selects the remote source, enters the
  test group, reads one article, and quits.
- Keep the test exact and short enough for default CI runs.

### Slice 7: Error Injection

- Add config-level command overrides.
- Support fixed response codes and connection-close actions.
- Add tests for temporary server failure and unavailable groups.
- Keep each injected behavior opt-in per test config.

## Non-Goals

- TLS.
- Real peer feeds.
- Authentication beyond canned `AUTHINFO` replies.
- Persistent spool mutation outside explicit post capture.
- Emulating INN policy details that `trn` does not observe.
